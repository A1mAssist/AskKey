# ADR 0007: Claude Code integration

## Status

Accepted for v0.2 (#112). Extends the supported clients in [ADR 0005](0005-distribution-and-client-integration.md) from Codex, Cursor and Grok CLI to four by adding Claude Code. The Broker protocol, permissions and approval model are unchanged.

## Context

Claude Code keeps user-scope MCP servers in `~/.claude.json`, a large file that running sessions rewrite often (project state, history and other settings live in the same file). It exposes an official CLI for MCP servers: `claude mcp add-json <name> <json> --scope user`, `claude mcp get <name>` (which health-checks an approved server), `claude mcp list` and `claude mcp remove <name> --scope user`. Hooks live in `~/.claude/settings.json` under `hooks`, keyed by event (`UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, …), each with matcher groups of `{"type": "command", "command": …, "timeout": …}` handlers. A real user's settings file can already hold many hook events from other tools. A `PreToolUse` command hook receives JSON on stdin (`session_id`, `hook_event_name`, `tool_name`, `tool_input`, `tool_use_id`) and can deny a call with `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": …}}`, the same envelope the Grok CLI adapter already emits. MCP tools appear to hooks as `mcp__<server>__<tool>`.

## Decision

- **MCP configuration through the official CLI only.** AskKey never edits `~/.claude.json` directly. Setup runs `claude mcp add-json askkey '{"type":"stdio","command":"/Applications/Ask Key.app/Contents/Helpers/askkey","args":["mcp"]}' --scope user` after preflight, and rollback runs `claude mcp remove askkey --scope user` only for an entry AskKey added in the same transaction. An existing `askkey` entry with a different command, arguments or scope is reported and left untouched; a project- or local-scope `askkey` entry is reported as conflicting, not overwritten.
- **Preflight** resolves the `claude` executable the same way the other adapters resolve their CLIs, records `claude --version`, and requires the commands above to exist. The minimum supported version is the oldest version on which the adapter's tests and the real-client check (#127) pass; it is recorded in `docs/client-integrations.md`. Unsupported or unknown versions stop setup with a clear state.
- **Verification** requires `claude mcp get askkey` to report the user-scope stdio server with the expected command and a connected status, then the shared helper contract ([MCPHelperContract](../../Sources/AskKeyIntegrations/MCPHelperContract.swift): `initialize`, `tools/list` with `list_credentials` and `run`, helper signature, Broker health). Configuration presence alone is not "connected".
- **Discovery hook in `~/.claude/settings.json`.** AskKey owns exactly one handler per event it needs, identified by its command (`"/Applications/Ask Key.app/Contents/Helpers/askkey" hook claude`): `UserPromptSubmit` (starts a turn), `PreToolUse` with matcher `Bash|mcp__askkey__list_credentials`, `PostToolUse` and `PostToolUseFailure` with the same matcher. The writer appends these handlers, preserves every other key, event, matcher group, handler and their order, keeps file permissions, writes atomically after a private backup, and reads back the result. Unknown content in an AskKey-owned handler is reported, not overwritten. Removing the integration removes only the owned handlers.
- **Helper `hook claude`** reuses the command discovery flow ([CommandDiscoveryHook](../../Sources/AskKeyHelper/CommandDiscoveryHook.swift), [DiscoveryTurnStore](../../Sources/AskKeyHelper/DiscoveryTurnStore.swift)): `UserPromptSubmit` begins a turn for `session_id`; `PreToolUse` on `Bash` whose command is an SSH connection is denied with the shared reminder until a `mcp__askkey__list_credentials` call in that turn settles (`PostToolUse` or `PostToolUseFailure`), using the existing 30-second no-progress release. Every other event or tool is allowed with no output. The hook never runs tool input, never reads credentials and never grants access.
- **No permission changes in Claude Code.** AskKey does not add `permissions.allow` entries; Claude Code's own tool approval remains in force alongside AskKey approval.
- **Readiness** follows the other command-hook clients: adapter `connected` after MCP verification; product `verifiedConnected` when the owned hook handlers read back as configured. Readback proves configuration for a new session, not that a running session loaded it.
- Development and E2E builds use the isolated client home ([AgentClientConnector](../../Sources/AskKeyAppKit/AgentClientConnector.swift)); tests use synthetic `claude` executables and settings files, never the user's real files.

## Consequences

Using the official CLI avoids racing Claude Code's own writes to `~/.claude.json`, at the cost of depending on its command contract; preflight and version recording make that dependency explicit. The settings writer must be as conservative as the Cursor hooks writer because the file is shared with other tools. Claude Code becomes the fourth supported client, listed first in Agent access. Implementation: #113 (adapter), #114 (hook), #115 (Agent access), #116 (docs); real-client acceptance happens in the release ticket.
